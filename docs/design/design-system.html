branchling-ui

Ledger

A calm, dense interface for a backlog that lives in markdown and is driven by a CLI. It reads like a well-kept ledger: every number traceable, every change signed and explained.

Source of truth: docs/design/tokens.css, tokens.json, components.css. Zero dependencies, system fonts, no build step — the same constraints as the app (docs/architecture.md).

Principles

They settle arguments about details. When two good options compete, the one that serves a principle higher on this list wins.

  1. branchling said it, we show itCounts, refusals and errors are shown as the CLI gave them. A refusal never looks like an empty list; nothing is derived from guessing at names.
  2. Every write names its commandA dialog that changes the backlog shows the exact branchling command it will run and asks for the reason the command requires.
  3. What needs a person comes firstQuestions waiting on someone, tasks that may start now and failing checks are one glance from anywhere.
  4. Label first, colour secondEvery status and priority has its text on screen. Colour is a role layered on top, and neutral until the vocabulary arrives from the CLI (UI-18).
  5. Dense, never crampedFifty rows must scan without fatigue: tabular numbers, mono ids, one accent, quiet borders, generous line height in prose.

Colour

Neutrals tinted toward moss, one teal ink reserved for what can be clicked, and five roles for meaning. Components use semantic tokens only; light and dark are one light-dark() declaration each.

Status and priority roles

A role says what a value means to the reader, not which value it is. The view model maps a status or priority to a role; the page maps a role to colour. Until UI-18 brings the vocabulary, every value maps to neutral.

Shapes back up colour: a status is a round pill with a dot, a priority is a square mono tag, muted has a hollow dot and progress a ringed one, so the meaning survives greyscale and colour blindness.

Space and layout

A 4 px grid. Controls are 28, 36 or 44 px high (44 on touch-first places). Sidebar 240 px, content up to 1280 px, task panel 544 px; below 1024 px the sidebar becomes a drawer, below 640 px tables fold into lists.

Shape, depth, motion

Radius 4 for tags, 6 for controls, 10 for cards. Three shadows, used only for things that float; in dark mode depth comes from lighter surfaces. Motion is 120–320 ms on transform and opacity, and off under prefers-reduced-motion.

Icons

One sprite (icons.svg), 24 px grid, 1.75 stroke, drawn for this product so nothing is fetched. Always next to a label, or with an aria-label on an icon-only button.

Buttons

One primary button per view or dialog: the write the reader came to make. Teal is never used for decoration, so it always means “this does something”.

Focus: tab to any button — 2 px teal ring, 2 px offset.
Do

Name the button with the verb and the object: “Take HB-38”, “Record decision”, “Declare release”.

Don’t

Use “OK”, “Submit” or “Confirm”. The reader should know which command runs without reading the dialog twice.

Forms

Labels above fields, hints below, errors in words with an icon and aria-invalid. A reason field appears exactly when the command requires one.

Overlays

The task panel slides in from the right over the list it came from (its id is in the URL). Dialogs are for one write each. Toasts confirm a write that succeeded and link to the result; failures are never toasts.

View states

Loading, empty, error, refusal and stale, as in the ui-web skill. A refusal is amber and reads as an answer; an error is red and reads as a fault; stale is blue and keeps the data on screen.

Accessibility

WCAG 2.2 AA is the floor, in both schemes.

  • Contrast checked by script for every pair (text 4.5:1, UI 3:1).
  • Real button and a href only; tables with th scope; one h1; a skip link first.
  • Focus ring on everything focusable; the sticky top bar never covers it (scroll-padding-top).
  • Targets at least 24 × 24 px; touch-first places use 44 px controls.
  • The task panel and dialogs trap focus, close with Esc and return focus to what opened them.
  • Live regions: results aria-live="polite", errors and refusals role="alert", loading aria-busy.
  • Keyboard: / find, j/k move in lists, Enter open, Esc close, g then d to Decisions.
