# Security policy

## Supported versions

Before the first release, security reports are assessed against the current
`main` branch. After releases begin, only the latest published version and
`main` receive security fixes. Older releases, forks and unmerged branches are
not maintained security lines.

## Reporting a vulnerability

Do not open a public issue or pull request for a vulnerability that has not
been disclosed yet. Use
[GitHub private vulnerability reporting](https://github.com/limackk/branchling-ui/security/advisories/new)
instead. Include the affected commit or release, the impact and the conditions
needed to trigger it, a minimal reproduction, and a suggested fix if you have
one.

A vulnerability in branchling itself, rather than in this interface, belongs to
[branchling's own security policy](https://github.com/limackk/branchling/blob/main/SECURITY.md).

Reports are assessed as maintainer availability permits. This project does not
promise a response, fix or disclosure date.
